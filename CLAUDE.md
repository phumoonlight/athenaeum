# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

`athenaeum` is a personal learning workspace — a single git repo holding many small,
unrelated coding experiments accumulated since 2016. It is **not** an application and
has no root build system, no root `package.json`, no test suite, and no CI.

Consequences for working here:

- There is **no repo-wide build, lint, or test command**. Every command is scoped to a
  single project directory. Always `cd` into the project first and read its
  `package.json` / `go.mod` / `pubspec.yaml` / `requirements.txt` for the real commands.
- A project may carry its own `README.md` and `AGENTS.md` (design, invariants, gotchas) —
  e.g. `workshop/site-marker/AGENTS.md`. Read them before changing that project.
- Projects are independent and must not import from each other.
- Dependencies (`node_modules`, build output) are never committed — each project carries
  **its own `.gitignore`**. The root `.gitignore` only ignores `tmpclaude-*`, so a new
  project without its own `.gitignore` will leak `node_modules` into git. Add one when
  creating a project.

## Layout

```
workshop/       active, in-progress projects
archives/<year>/   finished or abandoned projects, filed by the year of the work
```

- New work starts in `workshop/<project-name>/`.
- When a project is done or abandoned, move the whole directory to
  `archives/<year>/<project-name>/`. Some years carry a one-line `README.md` describing
  that year's context (e.g. `archives/2021/README.md` → "Hobby projects").
- Archived projects are historical records: **do not modernize, refactor, or fix them**
  unless explicitly asked. Old code is expected to look old.
- `1.json` at the root is unrelated scratch data, not part of any project.

## Project shapes you'll encounter

Mostly Node/JS/TS (Express, Next, Nuxt, Vue, Angular, Nest, React), plus Go
(`archives/2021/learn-go*`), Python (`archives/2022/learn-python/*`), C#
(`archives/2021/learn-cs`), Flutter (`archives/2025/learn_flutter`), Java
(`archives/2017/*`), and plain HTML/C. A few are non-npm: browser extensions
(`workshop/youtube-sidebar-live` — MV3, no build step, loaded unpacked) and monorepos
(`archives/2025/cms` — npm workspaces + turbo, so `npm run dev` there fans out via turbo).

Typical single-project workflow:

```powershell
cd workshop\test-smtp
npm install
npm start
```

## Formatting

The root `.prettierrc` is the default style for the repo: **no semicolons**, single
quotes, 2-space indent, `printWidth` 100, LF endings, es5 trailing commas. A project may
override it with its own `.prettierrc` — the nearest config to the file wins, so check
for one before formatting. VS Code is set to format on save with Prettier for JS/TS.

`.github/modernize/` is generated by the GitHub Copilot app-modernization extension, not
hand-maintained project code.
